# Data contracts

D-377-STORY: existing grammar-v1 scenario type, checkpoint story or registry id
integer; checkpoint 16..22 maps to N1..N7, registry 16..19 maps to N8..N11.
Visible titles carry the N label. Trunk and fork entries preserve the existing
family schema and exact expected refusal/state/flow semantics.
D-377-CLAUSE: existing clause type with new story identity, unique checkpoint
atom identity, class and existing semantic tie. N5 notes distinguish observed
money flows from unresolved design authority. Existing clause rows unchanged.
D-377-CORPUS: existing Lean-driver output schema; discovered input scenarios
and generated story identities reconcile exactly, including every fork.
D-377-EXTENT: exact family identity sets and executed action totals; original
104/115 plus new executed actions, not file count masquerading as execution.
D-377-PROVENANCE: runtime receipt binds command, SHA, exit, evidence path/hash
and all denominators. Predecessor landing confirmation is separate authority.
