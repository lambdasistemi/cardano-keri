# Data

DATA-279-OUTPUT: raw provider UTxO with transaction hash/index, full address, lovelace/assets, raw inline datum bytes and provider JSON when available. Every occurrence remains in the denominator; errors attach to rows.
DATA-279-REPORT: examined, decoded, failed_decode, counts keyed ACTIVE/ARMED/FROZEN/TOMBSTONE/UNKNOWN; rows containing output identity, AID, asset, address, value, role, decode error and non-ACTIVE resolution fields. examined = decoded + failed_decode. Unknown addresses cannot count as absent; duplicate identities are reported, never silently deduplicated.
DATA-279-PROVENANCE: manifest/hash, request URLs/bodies, raw page responses/headers, times and tips, final-page evidence, reference verification and acquisition errors. A replay proves behavior over supplied rows only; live completeness needs successful enumeration and reconciliation.

Report JSON wire contract for the gate: each row retains tx_hash, tx_index, address, value, asset_name, state, and aid (raw 32-byte CESR digest as hex; aid_format="cesr-digest-hex"). Non-ACTIVE decoded rows include deadline (integer or null) and a nonempty resolution string naming the actor or explicitly no authorized exit. Error rows include a nonempty error string. Report counts include every named role, derived from rows. duplicate_identities maps each repeated asset name to its output-ref list. Live report adds complete boolean, provenance {endpoint,manifest_sha256}, and artifacts [{path,sha256}] for retained raw request/response evidence, including tips. Relative artifact paths stay inside output-dir.
For each attempted HTTP response, provenance.requests records {method,url,body,status,response_file,headers}; body is the JSON request object ({} for no body), response_file is a relative raw-byte file listed in artifacts, headers has lower-case names. These records reconcile against the observed test server exchange, so forged or missing raw acquisition evidence cannot pass merely by supplying a hash.
